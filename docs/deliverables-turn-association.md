# 产物总列表与回答卡片的关联

总列表位于右侧“会话详情 → 总产物”，按业务 conversation 汇总路径及各轮关联。
回答卡片只展示能确认属于该轮的交付集合。两处数量不同本身不是错误：旧记录可能没有
可信轮次，分页可能还未加载生产它的回答，显式空声明也不应由自动推断补齐。

本次核实到的代码问题包括：

- 真实 Pi/MCP 联测另复现显式登记与历史回填并发，读后写事务升级 WAL 快照时
  返回 SQLite `database is locked`，显式产物集合未能持久化；替换、清空、移除及隐藏
  事务现在先取得 SQLite writer，再读取归属，不修改用户元数据。
- 轻量刷新发送 `isUser`，嵌套 Rust 请求结构只接受 `is_user`，请求无法反序列化。
- 完整历史能利用提示指纹关联轮次，轻量请求重建空 blocks 后丢失了指纹。
  完成后的 parser ID 不等于发送端 client ID 时，关联结果可能与初次加载不同。
- 刷新只取最后 200 条消息，却整体替换已加载分页的产物集合；分支刷新也遗漏源对话作用域。
- 双端时间戳兜底可能把不同任务、引导消息或未加载页面的记录挂到附近回答。
  相同提示的旧轮次先匹配时，还可能抢走当前页的对应关系。
- 首轮显式登记可先于历史快照写入，本地已接受的用户消息原来未参加轻量关联查询。
- 大用户图片延迟加载后不能重新计算原提示指纹，业务历史必须保留投影前的身份。

修复使完整读取与轻量刷新共用内容指纹和精确 ID 关联。身份引用在图片延迟加载前生成，
随分页传输，业务消息持久化时作为 CodeG 元数据保留，不修改原生 rollout。
不改变数据库 schema，旧业务消息 JSON 仍可读取；旧版本会忽略新增元数据。
轻量请求兼容两种字段写法，分批覆盖所有已加载消息，每批最多 200 个引用，不发送正文、
不读取整份原生历史。刷新仍保持单飞、迟到事件再读，以及快照/任务代次校验。
分支查询遵循原 fork 边界，继承文件的操作使用真实所属 conversation。

显式 `success`、`success_empty` 和部分成功的权威规则保持不变；自动推断仍过滤临时文件、
缓存及内部脚本。晚到 AIR 文件报告按真实 turn_run_id 写回已完成原轮次并发出刷新事件，
不会改投当前轮。普通 MCP 登记仍要求可校验的活动轮次，不能确认时明确拒绝。
有相同内容的重复提示按最近的指纹匹配对关联；等距冲突和无可靠身份的历史记录不猜测，
保留总列表，不在最新回复尾部伪装为该轮交付。

同一路径复用一个文件身份，逐轮关联保留声明元数据；不同路径分别分组。
这些是关联历史，**不是文件内容快照**。打开、下载使用经重新验证的当前路径内容；
旧版本内容被覆盖后不宣称仍可下载。

回归覆盖显式/自动/空集合、部分失败及重试、同路径多轮、重复提示与时钟偏差、晚到 AIR、
分页刷新、旧响应、分支边界、大图片投影以及历史孤立记录。Windows 验收另外使用真实 Pi
及 companion，在隔离 Server Web 和 Setup 页面验证实时卡片、刷新、外部投递与下载。
最终结果以发布 commit 的 CI 和重新下载资产的报告为准。
