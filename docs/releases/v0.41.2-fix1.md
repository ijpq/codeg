# 0.41.2-fix1 — reliable business context and packaged recovery

Cross-Agent handoff now preserves actual business discussion rather than only
current-task summaries. The old bridge truncated individual text blocks and
still advanced the whole-record cursor, hiding untransferred corrections.
Accepted requests now persist exact UTF-8 ranges, reserve space for recent
business discussion, prioritize earlier user requirements over long assistant
narratives through a separate bounded indexed window, and deliver uncovered
older ranges without repeatedly
injecting accepted text. Source prose changes invalidate its coverage;
duration/usage backfills do not. Native sessions, credentials, compression and
writers remain independent. Additive migration metadata is retained on rollback
and does not rewrite native transcripts or remove business history.

`get_session_info` now supports snapshot-bounded original-prose pages through
`history_cursor="start"`, exact returned next cursors, or
`history_cursor="sequence:<number>"`. Long messages resume within the original
record. Pages stay bounded and indexed; the previous compact recent view remains
compatible. Private reasoning, raw tool frames and image bytes are not replayed
as another engine's messages. Missing relevant history remains explicitly
undeclared as delivered; access to a reference is not proof of model receipt.

Pi-native base rules, skills, memory, ledgers and extensions will be configured
separately. This release does not perform local migration, change Codex settings
or add a base-configuration synchronization layer. The existing full applicable
rule bridge is retained until required constraints exist on the target. Digests
avoid repeated unchanged rule bodies. The withdrawn automatic global-sharing
draft is not part of this release.

The fixed private group is Pi ACP 0.0.34-codeg.3
(f42ee21c0a4bb79d0fd2c33b399ba2bd7f7fb70c), Pi 1.4.0 and Node 24.16.0.
The adapter's optional original-skill-path contract is not automatically
configured by CodeG. Both Windows forms carry matched ACP/MCP/native runtimes,
frontend assets and migrations without depending on a global npm installation.

All unpublished fix1/fix2/fix3 restore fixes are retained: stable business
binding for Codex and Pi, active-first-turn identity, ordered readiness receipts,
old callback guards, readable failures, and durable composer queues. The final
Server and installed Setup must separately pass actual-composer sends with
native runtimes, old fix6 business data, a five-second delayed restore, subsequent
rounds, conversation changes, reload, reconnect, two-way handoff and a real
process restart. Stable message IDs must reach the selected engine once and
finish with replies; ready/HTTP success alone does not count. The final runtime
and model requests also check current business corrections in both directions.
All previous Pi, external delivery, service-tier, duration, deliverable, Office,
native Plan/Goal and virtualized-scroll gates remain in scope.

Tests using deterministic model endpoints prove request content, protocol and
real native tool execution; they do not prove an authenticated model's autonomous
小弟 delegation, skill selection or material-only wording. No isolated live-model
authentication is available. The user's live fix6 page/localStorage was not
accessed; its exact readiness gate is not claimed as observed. Real relay
priority forwarding, speed and billing remain unverified. Pi does not implement
native Codex Plan/Goal, and private compressed contexts cannot be shared
losslessly. Unverified behavior is reported separately from package checks.

No running user Server/Setup or external automation is changed. Publication does
not authorize installation. Both assets must pass draft verification and a
fresh post-publication download with hashes and resource/runtime checks before
safe cache cleanup is allowed. Source, lockfiles, user data, packages and final
diagnostics are retained; Docker/container storage and active files are excluded.
