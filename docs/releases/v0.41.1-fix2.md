# 0.41.1-fix2 — restore binding through the first completed turn

The unpublished fix1 draft passed both Windows builds but failed isolated Setup
acceptance: its first Codex composer round completed, while the next message did
not execute. The native log confirmed `active_turn_attached` for the same
connection. Two frontend restore branches ignored that valid result, leaving
its business conversation and MCP binding unset. The idle composer then waited
for a binding the backend had already confirmed.

Both Windows Server and Setup now accept that verified identity without
replacing the running writer or opening the prompt latch prematurely. The
backend returns an event cursor read with the active lifecycle; a delayed
receipt cannot resurrect a turn whose terminal event already arrived. Older
servers without the optional cursor retain a conservative pre-request guard.
The existing persistent queue and client message IDs remain responsible for
retention, acknowledgement and retry. This does not promise exactly-once
execution for arbitrary native protocols across process failures.

Regression coverage includes Codex and Pi, Web attach and desktop events, a
fresh first-prompt connection restored while running, subsequent sends, and
completion overtaking the restore response. Packaged acceptance uses the actual
composer across five rounds, tab switches, reload, connection loss, failed
restore/retry and process restart, with bounded state diagnostics on failure.

This release retains the [fix1 changes](v0.41.1-fix1.md): complete versioned rule
handoff and repair of previously truncated rules, verified readiness, stale
subscription isolation and private native Codex catalog resolution. Existing
business Agent sessions, Pi capabilities, external delivery, ordinary-task
duration, artifacts, Office review, native Plan/Goal and virtualized scrolling
remain included. No user instance is installed, replaced or restarted by release.

The additive rule-delivery migration and offline whole-group rollback procedure
are unchanged. Pi ACP remains `0.0.34-codeg.2`, commit
`0d0fbe08a0a7eaacbb1061aea79c5fcb6a1e26c5`, with Pi 1.4.0 and Node 24.16.0;
Codex remains private 0.162.1-codeg.1 and ACP 2.2.2. The application binding fix
requires no new Pi adapter release. Both packages carry their matching MCP,
runtime group, static frontend and migrations.

Native CLI/ACP/MCP execution against deterministic local model endpoints checks
protocol and actual request content, including complete long rule tails and
updated rules for existing sessions. Authenticated live-model “小弟” delegation
and document presentation behavior remain unverified without an isolated model
configuration; deterministic responses do not establish model compliance. Relay
service tier requests do not establish actual acceleration or relay pricing.
Unsupported engine capabilities remain explicit. Full package acceptance,
public re-download and SHA256/inventory results are retained in release evidence.
