# CodeG 0.41.3-fix4

Windows Setup 与 Server 共同保留 Pi 上下文压缩、消息受理及真实执行终态修复，并修正
切页或刷新后将仍在运行的压缩误显示成完成的问题。

fix3 的最终安装包页面验收捕获了实际故障：Pi 正在压缩，后端实时快照和新持久表都为
`in_progress`，但历史适配器给普通未配对工具的默认“已结算”状态覆盖了卡片的运行态。
现在卡片优先使用原生压缩生命周期，再兼容旧协议的通用工具状态；保持真实阶段、已耗时、
成功/失败/取消一致，不制造百分比、不重发 prompt，也不把仍在执行的任务提前结束。
新增三项回归先复现失败，另有实际历史消息适配到渲染的冷页回归。

继续包含 fix3 的同请求受理与有界原生健康检查、新旧 compaction 事件、先收束原生执行再
结算取消/故障，以及按业务/session/连接/轮次持久保存成功、失败、取消压缩记录的修复。
原生 JSONL、业务历史和用户文件不改写；没有终态的重启中断明确保留结果未知。

完整保留业务对话/独立 Agent session、增量上下文与恢复队列、多 Provider、Fast 请求档位、
外部消息、整轮耗时、原生 Plan/Goal、产物与 Office 审阅、虚拟列表及正常追底。
本轮不迁移本机 Pi 基础设施，不新增跨 Agent 基础配置同步层，不操作用户正在运行的实例。

运行组：Pi ACP `0.0.34-codeg.5` / `580f786dd9c5c18513971a419ad136330b493531`，
Pi `1.4.0`，Node `24.16.0`；Codex CLI `0.162.1-codeg.1` / ACP `2.2.2`；
codeg-mcp 与主程序同版。基线 upstream `v0.41.3` /
`ddd1f09fc5dd2f464e68bb4b5a2bbf51257ecfc5`。

未发布的 fix3 标签、双包和原失败证据保留；不复用其成功构建代替 fix4 的精确提交检查。
双包门禁继续要求隔离安装/升级、最终运行时与实际输入框长压缩超过 30 秒、真实回复一次、
下一轮、停止/失败/重试、切页/重连/重启、多端、回滚、正式重新下载及资源/SHA256 校验。
全部成功之后才允许审计并清理可重建缓存。

验收的模型端使用隔离确定性 HTTP 服务，Pi/Codex CLI 与 ACP 均为最终包内真实组件。
这不代表用户认证中转的实际加速、费用、自主推理或用户特定 Skill/委派规则已验证。
