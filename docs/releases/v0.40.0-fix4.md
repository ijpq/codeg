# v0.40.0-fix4

基于 upstream v0.40.0（`95fd81df4374753c460b5cb0ed01de8f1ea24702`）。

本版保留同一业务对话切换 Codex／Claude Code／Pi 的全部实现：稳定的业务 ID、
一份持久分页历史、各引擎独立 session／认证／writer／配置，以及轮边界切换、失败回退、
跨端 CAS、持久收据和有界增量交接。可见历史与目标模型实际收到的上下文分别验证。
原生自动标题不覆盖业务标题，迁移停用及离线整组回滚保留历史归档。

Pi 初始化和恢复校验真实 JSONL 身份及路径；定制适配器连接原生 steer、尾部 clone、
Pi 1.4 原生 MCP，以及 companion 的真实子任务、取消、结果回收和产物登记。
业务 ID 外部投递固定接收时的 Agent、session、切换代次及执行配置，提供约束、幂等键、
附件、queue／steer、状态查询与取消。切换中明确拒绝，过期连接不静默改投；不确定投递
不自动重发。没有检查或修改 2K 等外围程序，旧接口边界见[投递文档](../business-message-api.md)。

Pi Fast／Speed 在支持的 GPT Responses 接口请求 default／priority，独立于推理强度，
默认关闭。按实际返回区分“已请求”、中转报告和上游报告；真实用户中转的服务档位、
计费与加速效果未验证，不套用官方价格，不自动开启或降级。

普通任务按真实任务 ID 对齐整轮耗时，保留原生 duration，并在 usage 先到时继续有界补齐。
先前误加的 To-dos／Goal 计时字段已精准撤销，有效的原生 Plan／Goal 和滚动修复保留。
直接执行／先规划／目标执行继续使用实际能力；切主 Agent 时暂停已有原生 Goal，
切回不自行继续。Pi 没有原生 Plan／Goal，不用提示词模拟。

总产物入口位于右侧“会话详情 → 总产物”。单轮卡片修复字段兼容、指纹、分页、分支、
旧响应和 SQLite writer 竞争，无法可靠关联的旧记录保留在总列表；显式空集合仍具权威性。
Office 预览只由本轮正常完成并结算的最终交付集合驱动，使用真实稳定副本；过程修改、
后台对话和重复事件不抢占预览。保留长历史虚拟列表、正常追底与用户主动上翻行为。

补充修复并复现同工作区并发任务的归属漏洞：`ambiguous` 观测曾被文件类型规则放行，
写入单轮产物并可选为 Office 主预览。现在不创建这类单轮关联；合格文件保留在总列表，
不覆盖已有显式登记。旧错绑根据可靠观测过滤，原始记录、文件和副本保留；显式登记与
可信独占推断的预览继续有效。真实 Pi 双会话、文件监听和 Office 转换链路列入双包验收。

本次另确认隔离 Office 测试工具在下载后会自行升级，导致测试输入版本漂移。测试子进程
现禁止自更新和自动安装，并在真实转换前后核对实际路径与 SHA256；不改用户的 Office
设置或全局工具。完整性回归列入正式包发布前、发布后的 Windows 验收。

fix3 发布后曾在隔离 Server 验收中出现一次 32 GiB 分配失败。该版本已标为预发布，
保留 tag、资产与[原始失败证据](https://github.com/ijpq/codeg/actions/runs/40449537644)。
三次优化分配栈诊断均通过完整 Setup／Server 页面流程，未复现异常分配，最大记录分配
为预期的 Brotli 缓冲区。固定 Office 测试工具后，原发布双包的三次完整复测也均通过
32 项实际页面检查，转换器版本及哈希未变化。根因仍未确认，本版没有加入猜测性应用补丁，也不宣称已经修复
该内存异常。诊断通过不替代本版精确提交的正式包验收。

Windows x64 Server ZIP 与 Setup 同时携带匹配的 codeg-mcp、私有 Node 24.16.0、
Pi 1.4.0 和 pi-acp 0.0.34-codeg.2（commit `0d0fbe08a0a7eaacbb1061aea79c5fcb6a1e26c5`）。
保留来源、锁文件、逐文件清单和许可证；不覆盖共享 CLI 或复制其他引擎的认证。
Setup 沿用用户的外部 Codex／Claude 配置，OfficeCLI 仍为可选转换器。

验收以 Windows 编译与共享逻辑为门禁；Linux runner 继续运行通用前端、浏览器和无桌面
依赖的 parser／HTTP 测试，不等待 Linux／macOS 客户端。正式双包仍须验证安装、启动、
升级、重启、整组回滚、真实页面、资源、依赖、迁移，以及发布后重下载和 SHA256。
原生 CLI／ACP／MCP 联测使用隔离确定性模型端点，不冒充真实账号推理验证。

能力边界继续保留：跨引擎原生上下文不能无损导入；Pi SSE 与任意旧 fork point 不支持，
fallback 明确标注；SQLite 与任意 ACP 之间没有跨进程原子提交，交付未确认时不承诺
exactly-once。没有修改、替换或重启现有用户 CodeG。
