# CodeG v0.30.7-fix1

Codex 完成后，辅助 AIR 产物报告不再阻塞 ACP prompt 响应和任务完成状态。
升级基线为上游 v0.30.7，保留定制分支、产物、引用、模型隔离和大历史分页能力。

## 根因与修复

- npm 发布的 codex-acp 1.10.0 和 1.11.0 在 `prompt()` 的 `finally` 中等待
  `publishAgentFileChangeReport`。AIR 使用独立只读 fork 和模型审计，属于辅助操作；
  等待它会推迟 `stopReason`、active prompt 清理和 CodeG 的完成落库。
- 旧 CodeG 的异步 AIR 兼容补丁仅覆盖 1.6.2，当前固定的 1.10.0 不会应用该补丁。
- 新补丁单独覆盖已验证的 1.10.0/1.11.0 正式包，精确匹配锚点后从缓存启动派生副本。
  不修改安装的 npm 包、配置或用户会话。仍使用上游固定的 1.10.0，不强制升级 CLI。
- AIR 在 prompt 清理完成后的下一事件循环启动，捕获原 session、turn、request ID
  和工作目录。迟到结果按原 turn-run ID 入库，不能切换下一轮状态。
- AIR 文件验证通过独立、有界 worker 和 blocking 线程池处理，不再占用任务生命周期
  worker。过载继续保留 watcher 证据并记录降级日志；不关闭产物功能。
- 保留真实工具、原生子任务、通知队列、引导、消息排队、取消和恢复的协议等待。
  不依赖最终回答文本、前端隐藏状态或 rollout 轮询判断完成。
- 新日志区分主 turn 结束、ACP 结束就绪、AIR 开始/结束和原有完成持久化阶段。
  适配器诊断点依赖现有 `APP_SERVER_LOGS` / `CODEG_ACP_DEBUG` 日志开关，默认不启用全量协议日志。

  产物历史仍属于原 turn。快照测试验证报告不会改变重连/刷新得到的任务状态。

## 分阶段时间线

| 验证来源 | 修复前 | 修复后 |
| --- | --- | --- |
| 正式 npm prompt 方法、受控协议 peer | root/子任务完成 → AIR pending（active prompt 仍在）→ AIR 返回 → ACP end_turn | root/子任务完成 → cleanup/ACP end_turn → 下一轮可接收 → 原轮 AIR 补齐 |
| Rust 生命周期测试 | AIR 与终态共用串行 worker | 刻意锁住 AIR 写入时终态仍落库；解锁后原轮产物补齐 |

本地受控方法测试中，root 完成至 ACP end_turn 为毫秒级，AIR promise 未返回时
终态已可读取；这是隔离测试结果，不是现场 2k 会话的生产时延承诺。现场原记录
从 task_complete 至持久化 Completed 约 219.222 秒，其中产物处理约 0.497 秒。

## 发布资产与限制

- Windows x64 Server ZIP 与独立 SHA256；包含匹配版本的 Server、codeg-mcp、Web
  静态资源，SeaORM 迁移编译在 Server 内。不包含用户认证、数据或私有配置。
- 本次不部署或重启生产 CodeG。发布包使用 fork 的未签名服务器分发方式。
- 现场记录的 219 秒间隔不能全部归因于 AIR：正式包 AIR 预算为 30 秒，之前还存在
  通知队列和真实子任务等待。缺少生产适配器分阶段日志时，无法还原这些阶段的准确占比。
  本修复证实并移除了 AIR 对完成路径的串行依赖，没有声称已在生产样本上重放验证。
- 未验证的未来适配器版本会拒绝套用补丁并输出日志；需要重新验证兼容锚点。
- 进程退出后尚未送达的 AIR 报告不会自动重做模型审计，已持久化的 watcher 和声明产物
  仍可恢复。辅助队列超过 64 份报告时会明确记录 watcher 降级。
