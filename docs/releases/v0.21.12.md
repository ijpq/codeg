# Codeg v0.21.12

## Faster remote history loading

Codeg v0.21.12 reduces the amount of historical conversation work performed
when a workspace is opened through the web service, especially over Tailscale
or another bandwidth-constrained remote connection.

- **Hidden tabs no longer fan out full-history requests.** In the normal
  single-tab layout, only the active keep-alive tab fetches its persisted
  conversation detail. Switching tabs loads that tab on demand.
- **Tiled sessions remain complete.** When multiple conversations are displayed
  as tiles, every visible tile still loads its history while the active tile
  keeps its existing focus and connection behavior.
- **Historical JSON is compressed in transit.** The
  `get_folder_conversation` web endpoint now negotiates Brotli or gzip with the
  browser, substantially reducing text-heavy conversation payloads over remote
  links.
- **Compression is narrowly scoped.** Archive, backup, and other download
  endpoints are left untouched so already-compressed files are not compressed
  a second time.
- **Regression coverage is included.** Frontend tests lock in visibility-based
  detail loading, and a server test verifies gzip response negotiation.

This release does not introduce a database migration.

# Codeg v0.21.12 中文说明

## 更快的远程历史对话加载

Codeg v0.21.12 减少了通过 Web Service 打开工作区时需要读取、解析和传输的历史
对话数据，特别适合通过 Tailscale 或其他带宽受限连接远程访问的场景。

- **隐藏标签不再并发请求完整历史。** 普通单标签布局中，只有当前活动的
  keep-alive 标签会获取持久化对话详情；切换到其他标签时再按需加载。
- **分屏会话保持完整。** 多个对话以 tile 方式同时显示时，每个可见 tile 仍会加载
  历史记录，活动 tile 原有的焦点和连接行为保持不变。
- **历史 JSON 支持传输压缩。** `get_folder_conversation` Web 接口现在会与浏览器
  协商 Brotli 或 gzip，大幅减少以文本为主的长对话在远程链路上的传输体积。
- **压缩范围严格受控。** 压缩只应用于完整历史详情接口，不影响压缩包、备份和其他
  下载接口，避免对已压缩文件进行二次压缩。
- **补充回归测试。** 前端测试固定了基于可见性的详情加载规则，server 测试验证了
  gzip 响应协商。

本版本不包含数据库迁移。
