# CodeG 0.41.3-fix3

Windows Server 与 Setup 共用 Pi 压缩受理、真实执行终态和持久展示修复，不修改用户正在运行的实例。

Pi 1.4.0 的 prompt 确认在 preflight 压缩之后返回。普通 30 秒确认期限不能代表压缩失败；
适配器保留同一个请求，通过有界原生健康查询区分压缩、执行、卡死和进程退出，不重发任务。
兼容当前 compaction_start/end 和旧 auto_compaction_start/end。停止及真实故障必须先收束
所属原生执行；Windows 的后代进程清理不能只杀启动包装器，无法确认时保留 PI_STOP_UNCONFIRMED。

压缩统一显示真实阶段、已耗时、成功、失败或取消；没有百分比就不制造进度。
本次最终包诊断又发现 Pi 原生 JSONL 不保存失败/取消压缩，而 CodeG 历史刷新会移除临时卡片。
新 conversation_compaction 表记录原始业务、session、连接和事件身份及真实状态，按已有分页边界
合并展示；原生成功记录按 eventId 丰富字段并去重。它是显示数据，不是模型回复、整轮耗时或
伪造的原生历史。迁移为可回滚的增量元数据，降级不删除该记录。重启前未获终态的压缩明确标为
结果未知的中断；不永久转圈，不假称完成。完整原生记录、业务历史和用户文件均保留。

独立安全复现证明 kill_tree 0.2.4 遍历循环 PID 图会无限分配内存。随包保留 MIT 原始许可证的
小补丁在发现重复 PID 或当前应用进程时先拒绝整个歧义清理，再由调用方处理失败；正常树的顺序
及 include_target 不变。尚无调用栈证明 fix2 的 32 GiB Server 分配失败来自该缺陷，不能将其
描述为已确认的崩溃根因。原 fix2 tag 与资产保留为未验收预发布，不挪用其结果。

保留已实现的业务对话/独立 Agent session、增量上下文、恢复与队列、多 Provider、Fast 请求档位、
外部消息、整轮耗时、原生 Plan/Goal、产物和 Office 审阅、虚拟化和正常追底。本轮不做本机 Pi
基础配置迁移或跨 Agent 基础配置同步，不更改认证、Skill、账本、工作区和外围自动化程序。

运行组：Pi ACP 0.0.34-codeg.5（580f786dd9c5c18513971a419ad136330b493531）、
Pi 1.4.0、Node 24.16.0；Codex CLI 0.162.1-codeg.1 / ACP 2.2.2；codeg-mcp 与主程序同版。
基线 upstream v0.41.3 / ddd1f09fc5dd2f464e68bb4b5a2bbf51257ecfc5。

双包门禁使用隔离安装/升级旧数据及最终包内运行时，从实际输入框发送，检查长压缩超过 30 秒、
真实回复一次、下一轮、切页/刷新/多端、失败原因跨刷新保留、取消、重试、重启和回滚，随后重新
下载核对 SHA256、资源、运行依赖、迁移和提交。全部通过前不视为已验收，不执行缓存清理。
