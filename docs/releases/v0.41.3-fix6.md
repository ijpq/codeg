# CodeG 0.41.3-fix6

修复长历史 Codex→Pi 交接前置阶段在索引已 ready 时仍永久卡在不完整页的问题。
Windows Server 与 Setup 使用同一分页、业务交接和错误处理逻辑。

原算法先选择 25 轮，再检查单次 64 MiB 上限；超限后回退扫描仍以轮数为完成条件，
最终将预算不足误报成“索引仍在构建”。现场报告的 180.22 MiB 首屏与 64.66 MiB 第 13 页
在隔离合成结构中均已复现；未访问或复制用户的两份原始对话。

现在同时满足轮数目标与字节预算，优先完整用户轮次，必要时减少轮数或按完整 JSONL
记录切页。持久索引 v4 保存所有记录边界并校验连续性，游标严格推进；旧索引可重建，
原始历史不改写。跨页只补最多两条小型、身份一致的原生任务元数据，保留真正整轮耗时。
单条记录超过 64 MiB 时，专用路径用至多 32 KiB 的读取块进行两遍流式校验与预览，
总 I/O 与该记录长度成比例，未声称仍限于单页 64 MiB。预览每字符串至多 32 KiB、
总量至多 4 MiB，附原 session、路径、精确 byte range 与 SHA256；残缺图片不伪装可用。
全文继续保存在原生文件，可按需有界读取；引用和预览不代表目标已获得全部原文。

构建中、重建、索引容量、页预算、未提交记录、非法游标、源变化和解析错误分别处理。
