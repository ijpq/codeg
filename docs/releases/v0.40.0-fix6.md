# v0.40.0-fix6

基于 upstream v0.40.0（`95fd81df4374753c460b5cb0ed01de8f1ea24702`）。

保留未公开 fix5 的全部产品修复。fix5 草稿验收发现：源启动器缺失时恢复已失败，
但连接清理丢失原始错误，返回了误导性的“300秒内未完成（aborted）”；
验收还依赖具体 OS 错误文本。现通过一次性初始化结果传递真实失败原因，区分失败、
中断与超时，恢复及分支初始化共用处理。非终态警告不使正常初始化提前失败。
保留 fix5 tag 和失败证据，不将其描述为已正式发布或已通过完整验收。

预检会显式点选目标业务标签，避免刷新后保留的设备本地草稿焦点使测试等待错误页面；
源不可用验收失败时保留截图、打开标签及业务状态，不跳过原生恢复、交接和历史断言。
原生 WebView 没有模拟 viewport 时，从实际窗口读取并恢复尺寸，避免窄屏验收污染后续桌面导航。
窄屏验收先关闭导航抽屉，再验证 Agent 控件实际可点击，不把遮罩后的布局尺寸当作可用性证据。
中断恢复验收在测试启动器确认已启动且仍处于 starting_target 时中断隔离实例；
不再等待只能在握手成功后出现的 verifying_target，保留同一请求和原生 session 的重启恢复断言。

修复 Setup 缓存 Codex ACP 后丢失原 Node 模块查找链的问题，兼容已有本地/hoisted CLI。
Windows Setup 和 Server 同时携带私有 Codex `0.162.1-codeg.1`、Codex ACP `2.2.2`
和匹配 Node；测试不再向 Setup 注入 Server 的 `CODEX_PATH` 掩盖缺包。
显式 `CODEX_PATH`、`CODEG_CODEX_ACP_PATH`、关闭私有 CLI 的选项及用户原配置继续保留。
随包组件只写应用目录，不安装全局依赖、不搬迁认证或原生历史。

共同逻辑修复交接刷新相互作废造成的长期等待，并持久记录准备阶段、失败和成功。
状态查询使用一致数据库快照，旧 revision 不能覆盖新结果；慢/丢失提交确认仍可由持久终态收敛。
准备超时与激活提交分离。源 Agent 启动失败不隐藏切换入口；有可靠保存历史时仍可交接，
目标必须实际完成 session 和选择器校验。切换不会取消正常执行中的当前轮。

最新任务摘录优先于预算外旧历史；源实例的有效指令、操作边界、账本及分账读取要求，
以及 Skill 用途和准确路径随交接传入。规则和 Skill 全文按预算加载，缺口明确标注；
不读取另一实例的配置、凭证或私有记忆，不宣称已自动读取全部账本。
新增迁移只添加阶段和规则快照元数据，保留所有原会话绑定和历史。
回滚继续使用升级前离线数据快照与匹配整组旧包，不让旧迁移器直接打开新库。

Pi 设置版本与升级动作对应实际所选运行时，避免全局 `0.0.34` 冒充随包 `0.0.34-codeg.2`。
对话顶部显示 Agent、交接阶段和重试；最近对话默认十条，宽窄屏沿用共用界面。

保留 fix4 的同业务三引擎、外部投递、Pi steer/子任务/fork/MCP、Fast 档位、整轮耗时、
总产物/准确单轮卡片、Office 最终交付稳定预览、原生 Plan/Goal 和虚拟列表滚动修复。
总产物位于右侧“会话详情 → 总产物”。不修改外围自动化或正在使用的 CodeG 实例。

Pi `1.4.0`，Node `24.16.0`；codeg-mcp 与 CodeG 同版本。运行组保留来源、锁文件、
逐文件清单和许可证。Windows 自行构建 Setup 前须先准备精确普通 CI 的 Codex runtime：
`python -B scripts/fetch-tested-codex-runtime.py --repo ijpq/codeg --output-dir dist/codex-runtime`，
再执行 `python -B scripts/build-codex-adapter.py --output-dir dist/codex-runtime`；发布及候选工作流自动执行。

Windows 双包验收分别覆盖首次安装/升级、默认 Codex 发送和恢复、双向交接、源失败/目标失败、
重启、Server 多客户端、窄屏、产物/Office/滚动、依赖与迁移；正式发布后重新下载校验。
