# 0.41.2-fix4 — packaged recovery and traceable Windows acceptance

Retains the full [fix3](v0.41.2-fix3.md) application change: a draft acquiring
its own native session identity keeps its live connection instead of cancelling
it as a changed target. The four before/after Pi/Codex × Web/desktop regressions,
atomic business restore/readiness, durable queues and all earlier business,
context, runtime, external delivery, service-tier, duration, artifact, Office,
native Plan/Goal and virtualized-scroll work remain in scope.

The unpublished fix3 Windows builds passed, but its downloaded-package gate
failed when Server became unavailable after switching an old business back to
Codex. That original failure is preserved in run
[40848516137](https://github.com/ijpq/codeg/actions/runs/40848516137).
Two subsequent unchanged-binary diagnostics passed that Server path, including
actual replies and restart, then failed at the same fresh-draft test below.
They do not explain the original process loss and
is not evidence that a new product crash fix was made.

Package verification now records owned root PID, exit code/signal and the exact
intentional-stop reason, so final cleanup cannot misclassify an earlier crash.
Both stdout and stderr drain before the log is ended; an earlier closed stdout
cannot hide a later fatal stderr line. Scoped Windows Application Error metadata
is retained without event-message bodies or process-memory dumps. Process tests
cover unexpected exit, deliberate stop and a delayed stderr tail.

The multi-provider fresh-draft test now clicks the real Send control once,
allowing its normal disabled-until-initialized state to settle. Its initial
disabled state is recorded. It never pre-creates the business or connects through
an API. Historical recovery tests continue to send while native initialization
is held for five seconds, retain the real durable queue, and require exactly one
actual provider request and completed reply. This distinction prevents an Enter
on a disabled draft from being reported as a failed accepted delivery.

Narrow-layout verification also waits for the mobile navigation drawer to mount
before sending Escape. The strict actual-hit check remains; failure metadata and
a screenshot are captured before returning to desktop dimensions. This avoids
a responsive test race while still rejecting an Agent control under an overlay.

Every final Windows Server ZIP and x64 Setup must separately pass downloaded
inventory, dependencies, matching MCP, old fix6 data, actual visible composers,
model/Agent changes, restart/reconnect, upgrade and offline rollback. Ordinary
CI, source/tag/manifest hashes and re-downloaded assets must match this release
commit. Diagnostic script and original package source commits are distinguished.
Failed tags are never moved. Full outcomes are recorded in the
[combined checklist](../current-custom-release-checklist.md).
