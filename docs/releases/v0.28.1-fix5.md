# Codeg v0.28.1-fix5

## Restored sessions become send-ready reliably

- Treats a successful atomic restore response with `lifecycleState=ready` as
  the authoritative prompt-ready receipt, including when the backend reuses an
  existing connection and no additional WebSocket ready frame arrives.
- Revalidates an idle persisted Codex session when the browser has retained a
  stale prompt-readiness latch instead of permanently blocking later messages.
- Keeps messages submitted during restore in the existing durable queue and
  automatically retries them with the same client message ID after readiness
  is confirmed, preventing both loss and duplicate execution.
- Ignores restore confirmations for connections that have already been
  replaced, while preserving active-turn and provisional-branch semantics.

The Windows Setup and Server Web packages contain the same updated interface.

# Codeg v0.28.1-fix5 中文说明

## 会话恢复后可靠解除发送限制

- 将原子恢复接口返回的 `lifecycleState=ready` 作为权威的可发送凭据；即使后端复用了
  现有连接且当前页面没有再次收到 WebSocket ready 帧，也会立即解除发送限制。
- 当浏览器残留了过期的 prompt-ready 状态时，会重新校验空闲的持久化 Codex 会话，
  不再让后续消息永久停留在“等待会话恢复”。
- 恢复期间提交的消息继续使用既有持久队列，恢复完成后沿用同一个 client message ID
  自动发送，避免消息丢失或重复执行。
- 已被替换连接的迟到恢复结果不会覆盖新连接，同时保持运行中任务和临时分支的原有语义。

Windows Setup 与 Server Web 使用同一套更新后的前端资源。
