# Codeg v0.21.10

## Reliable, complete deliverables

- **Code changes are deliverables.** Agents are now instructed to publish
  meaningful source, test, documentation, and configuration changes before
  their final response, alongside standalone reports, media, archives, and
  other generated outputs.
- **Every turn is reconciled.** Codeg always performs a deterministic
  end-of-turn settlement. Successful declarations are preserved, while
  verified filesystem changes fill omissions. Failed, empty, or missing tool
  calls no longer disable recovery.
- **Safer incremental publishing.** `publish_deliverables` now merges by
  default and supports explicit `replace`, `remove`, and `clear` operations.
  Valid items survive partial rejection, so one bad path no longer discards the
  rest of the declaration.
- **Durable retry handling.** Each publish request carries an idempotency key.
  Codeg persists the result in SQLite, and the local `codeg-mcp` companion
  retries with the same key when a response is interrupted.
- **User intent improves attribution.** Output paths explicitly named in the
  prompt are recorded before execution and can promote matching ambiguous
  filesystem events without assigning unrelated concurrent changes to the
  conversation.
- **Broader accurate coverage.** Reconciliation includes modified source and
  test files, lockfiles, meaningful dotfiles, deleted code paths, CSV, SVG,
  XML, video, and audio outputs while continuing to exclude caches,
  dependencies, build intermediates, logs, and temporary drafts.
- **Clearer UI and diagnostics.** Deliverables now show code-change and deleted
  badges. Turn diagnostics expose declaration status, timestamps, errors,
  settlement status, and expected paths that were not observed.
- **Wire compatibility retained.** New and legacy `codeg-mcp` deliverables
  request shapes remain mutually compatible during upgrades.

The database migration is applied automatically on startup.

# Codeg v0.21.10 中文说明

## 更可靠、更完整的产物交付

- **代码修改也是产物。** Agent 在最终回复前会被明确要求发布有意义的源码、测试、
  文档和必要配置变更，同时继续发布报告、媒体、压缩包等独立输出。
- **每个 turn 都会结算。** Codeg 在 turn 结束时固定执行确定性产物结算：保留成功
  的显式声明，并用经过验证的文件系统变化补漏。失败、空声明或未调用工具都不会再
  关闭兜底。
- **更安全的增量发布。** `publish_deliverables` 默认采用合并语义，并支持显式
  `replace`、`remove` 和 `clear`。部分路径无效时，其他已验证条目仍会保存。
- **持久化重试。** 每次发布都带幂等请求 ID，结果持久化到 SQLite；本地
  `codeg-mcp` 在响应中断时会使用同一 ID 重试，避免重复写入或丢失成功结果。
- **用用户意图改善归属。** 执行前会记录 prompt 中明确点名的输出路径；匹配的
  ambiguous 文件事件可以提升为本轮产物，同时不会把无关并发变更串入对话。
- **覆盖更多真实产出。** 现在支持修改过的源码和测试、锁文件、有意义的 dotfile、
  删除的代码路径，以及 CSV、SVG、XML、视频和音频输出；缓存、依赖、构建中间物、
  日志和临时草稿仍会排除。
- **更清晰的界面和诊断。** 产物增加“代码变更”和“已删除”标识；turn 诊断会提供
  声明状态、时间、错误、结算状态以及未观测到的预期路径。
- **保持协议兼容。** 新旧 `codeg-mcp` 的 deliverables 请求格式在升级期间可以
  互相兼容。

数据库迁移会在启动时自动执行。
