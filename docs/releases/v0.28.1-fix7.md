# Codeg v0.28.1-fix7

## Large Codex conversations open as bounded pages

- Makes an ordinary conversation open return only the newest six user rounds;
  missing paging arguments no longer mean “parse the complete transcript”.
- Reads recent Codex history from the JSONL tail and persists rebuildable byte
  offsets, so reopening or paging a multi-gigabyte rollout does not rescan its
  prefix.
- Coalesces concurrent identical detail requests and prevents stale responses
  from replacing a newer conversation selection.
- Pages native and snapshot branch history without materializing the complete
  source and branch rollouts. A new snapshot branch immediately shows its
  inherited page instead of an empty placeholder.
- Keeps large tool results, reasoning blocks, and embedded images out of the
  first response. Verified previews render immediately; full data is loaded
  from its exact transcript range only when the user expands or views it.
- Keeps aggregate deliverable history out of the first page and retains the
  existing virtualized message list for bounded rendering.
- Adds privacy-safe timing, cache, byte-range, request-generation, and explicit
  read-only rollout composition diagnostics.

No conversation, branch, attachment, deliverable, or Codex rollout is migrated
or rewritten. The byte-offset cache is outside the database, contains no
message content, and can be deleted or rebuilt safely.

The Windows Setup and Server Web packages contain the same updated interface.

# Codeg v0.28.1-fix7 中文说明

## 大型 Codex 会话改为有界分页打开

- 普通打开会话只返回最近 6 个用户轮次；缺少分页参数不再等价于“解析完整
  transcript”。
- 从 Codex JSONL 尾部读取最近历史，并持久化可安全重建的字节偏移；重复打开或
  向前翻页时不再扫描数 GB 文件的前缀。
- 合并前端并发的相同详情请求，并阻止旧响应覆盖后来切换到的会话。
- native 与 snapshot 分支都按页读取，不再物化完整的源会话和分支 rollout；新建且
  尚无本地消息的 snapshot 分支会直接显示继承历史页。
- 首屏不再传输大型工具结果、reasoning 和内嵌图片：先显示已验证预览，用户展开或
  查看时才从原 transcript 的精确字节区间读取完整内容。
- 会话级产物历史不进入首屏，消息正文继续使用现有虚拟列表进行有界渲染。
- 增加脱敏的耗时、缓存、读取字节范围、请求 generation 日志，以及显式触发的
  rollout 组成只读诊断。

本版本不迁移、不改写任何会话、分支、附件、产物或 Codex rollout。字节偏移缓存位于
数据库之外、不包含消息正文，可随时安全删除并自动重建。

Windows Setup 与 Server Web 使用同一套更新后的前端资源。
