# v0.40.0-fix1

基于 upstream v0.40.0（`95fd81df4374753c460b5cb0ed01de8f1ea24702`）。

同一个业务对话现在可在输入区域切换 Codex / Claude Code。标题、历史、工作目录、
记忆、任务状态和产物归属保持一致；每个引擎保留独立 session、认证、writer 和模型/
推理/权限配置。切换正在执行的业务会先排队，准备成功后才交接，失败可重试。
不同业务和原有合法子任务仍可并行。

共享上下文采用显式、有界的增量桥及近期边界摘录，分别验证前台历史与实际模型请求。
共享记忆只保存用户确认的内容，区分 global/project/task，按预算加载并标出遗漏。
项目 Skill 主体复用 `.agents/skills`，显式调用时才把正文传给目标引擎。
原生上下文、压缩、私有记忆、工具句柄和认证不跨引擎复制。

数据库迁移只增加映射、业务历史、收据和共享记忆。未切换的旧对话保持原路径。
回滚恢复初始原生映射并保留新增历史归档。跨引擎业务分支使用明确标注的有界快照，
显示历史继续分页继承原冻结边界。崩溃造成发送确认不确定时保留草稿并停止自动重发，
不宣称任意 ACP 与 SQLite 之间具有跨进程原子提交。

保留普通任务“工作了 …”的原生整轮计时、独立于 usage 的有界耗时补齐、总产物列表、
真实 Plan/持久 Goal 控制和虚拟列表滚动修复。切离有活动 Goal 的主 Agent 前确认暂停，
回切不自动恢复 Goal；准备失败后已暂停的 Goal 也保持暂停。
原生 Goal 不接收普通消息块；切换后须先通过普通消息交付最新业务上下文，才允许
启动/继续 Goal。有界交接不要求把预算外的旧历史全部上传。

仅发布 Windows x64 Server ZIP、x64 Setup 及其 SHA256。Server 携带同版本 MCP/CLI、
前端资源、运行依赖与迁移清单。发布流程对下载资产验哈希，隔离试装/启动/升级 Setup，
并在两端实际页面复核耗时、产物、原生 Plan/Goal、长列表滚动和双引擎交接。

双引擎协议测试使用真实 ACP/原生运行时连接本地确定性模型端点，用于证明上下文和
协议行为。当前工作环境 Codex 未登录，不能将这些测试称为真实账号推理验证。
Office、桌面和宿主专属工具依赖目标环境的实际安装与权限。

详细映射、幂等策略、迁移和能力边界见
[单业务对话、多 Agent 架构](../single-business-multi-agent.md)。
