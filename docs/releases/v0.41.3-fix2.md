# CodeG 0.41.3-fix2

本版本发布后下载复验失败，已隔离为预发布，不作为已验收交付。隔离 Server 在旧数据
前端恢复流程发生 32 GiB 分配失败；原 tag、资产及失败证据保留，修复须使用新版本。
发布前通过的结果不能代替发布后失败，当前记录见[执行清单](../current-custom-release-checklist.md)。

修复 Pi 原生压缩期间 ACP 提前报失败、后台仍继续执行，以及取消时过早结算的问题。
Windows Server 与 Setup 使用同一核心和前端。

Pi 1.4.0 的 `prompt` 受理确认在 preflight 压缩之后返回。新适配器在普通确认期限
到达时核查原生状态，确仍压缩则保持同一请求，不重发 prompt；普通受理无回应、
健康检查失败、进程退出等保留具体原因并有界结束。当前 `compaction_start/end`
和旧 `auto_compaction_start/end` 统一处理。停止必须等原生本轮终态，取消期限届满
先确认所属进程退出，过期取消不能伤及后续轮次。

对话用同一条压缩记录展示真实阶段、已耗时及完成、失败或取消。没有上游百分比就不
制造进度。成功记录核对原生历史内容和 ID，避免实时与历史重复；不篡改 JSONL，
历史缺失的耗时和 token 数不填造。切页、重连、多客户端和重启继续使用同一状态链。

初始化时提前取得快照的客户端，会收到后续 MCP 就绪配置的有序事件，避免前端
永远停留在早期发送门禁；业务身份、session 和工作目录匹配校验保留。

原包的完整 Server 页面诊断又捕获了刷新后无法续发：输入框聚焦早于文件夹查询，
提前按业务 ID 恢复，前端连接缺少工作目录。文件夹加载后虽然再次恢复成功且复用
同一连接，旧合并流程却没有补齐该字段，消息保留在持久队列，无法通过发送门禁。
本版让聚焦等待具体目录，同连接恢复仅补齐缺失身份，不清空正在运行的状态，
不覆盖冲突目录，不放松工作目录匹配。六项 Pi/Codex、Web/桌面回归修复前全失败、
修复后全通过；相关连接、生命周期及发送队列共 292 项通过。最终包继续真实输入框
验证刷新后及后续各轮消息被接收并只回复一次。

发布前页面验收发现 fix1 的窄屏脚本未匹配包含快捷键的侧栏按钮名称，导致可能在
移动 Drawer 挂载前发送 Escape。本版修正该等待并保留阶段证据，工具栏仍须实际
可点击。回归在原选择器下两项失败，修正后五项通过。fix1 未正式发布，原部分结果
不能代替本版两个最终包的验收。

保留同业务多 Agent、独立原生 session、增量业务交接、恢复与持久消息队列、多 Provider、
外部投递、整轮耗时、真实 Plan/持久 Goal、总产物与每轮卡片、Office 交付审阅、
虚拟列表和正常追底。不迁移本机 Pi 基础配置，不更改用户认证、规则、Skill、工作区
或外围自动化程序；发布不包含安装或重启用户当前实例。

（`d5e7fd87ef4c277e3db46986adc21789076659f2`）、Pi `1.4.0`、Node `24.16.0`；

`v0.41.3`／`ddd1f09fc5dd2f464e68bb4b5a2bbf51257ecfc5`。
