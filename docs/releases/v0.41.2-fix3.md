# 0.41.2-fix3 — retain live drafts and verify multi-provider Pi composers

A native session ID arriving on the same draft connection previously differed
from its initial ID-less connect request. The frontend could tear down that
connection as a changed target, including an active prompt. Reuse now also checks
the verified actual session/business identity, Agent and workspace, while keeping
existing readiness/MCP, ownership and stale-request gates. Four Pi/Codex ×
Web/desktop regressions fail before the change and pass after it. Different
session, workspace and Agent requests still replace the appropriate connection.

Disconnect diagnostics name their fixed call site and share a lifecycle
generation across frontend APIs; they contain no prompt text or credential.
The user's supplied logs remain separate evidence. A new Provider is not assumed
to cause every disconnect, and the running user's page/localStorage was not read.

Both Windows packages are gated on real composers using their installed native
Pi/ACP/Node and two independent deterministic model APIs. The UI selects GPT and
`magpie-claude/claude/claude-opus-5-5`, sends the first input from a true unbound
draft, and continues after model changes, tab changes, reload and process restart.
Old fix6 Codex→Pi business data receives separate upgrade/restart coverage.
Assertions require the correct actual model request exactly once, a durable
completed reply, the same native session, and unchanged provider configurations.
No model is added to Codex. The harness removes inherited CODEG_* overrides
before assigning each isolated test's own paths; it never controls user instances.

All unpublished changes in [fix1](v0.41.2-fix1.md) and
[fix2](v0.41.2-fix2.md) remain: atomic business restore/readiness and durable queues,
full applicable-rule compatibility, ordered incremental business context and exact
coverage receipts, independent native sessions, Pi tools/steer/fork/MCP,
external-message contracts, service-tier handling, turn durations, accurate
per-turn/all artifacts, settled Office review, native Codex Plan/Goal and
virtualized scroll stability. The current scope is tracked in the
[combined checklist](../current-custom-release-checklist.md).
