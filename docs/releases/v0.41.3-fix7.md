# CodeG 0.41.3-fix7

修复 Setup 与 Server 共用的连接退出竞态，继续保留长历史 Codex→Pi 交接修复及此前全部有效功能。

fix6 的发布后下载包验收捕获：Pi 原生 fork 已创建独立 session，但连接线程退出
`block_on` 后，清理守卫在连接表锁竞争时调用 ambient `tokio::spawn`，产生
“there is no reactor running” panic。已退出的源连接残留在管理器中，writer 交接检查
随后超时并诚实回退 snapshot，原生分叉验收因此失败。fix6 已隔离为预发布，
原 tag、双包、哈希和证据保留，不能当作已验收版本。

清理守卫现在持有原运行时 Handle，即使在线程退出运行时作用域后，也能延后取得锁并
删除自己的连接；无竞争时仍同步删除，不影响其他连接。writer 真实退出与 reap 检查、
原生/快照分支区分和失败回退保持。新增两项回归覆盖锁竞争、Pi/Codex、其他连接保护
及无竞争路径；精确源码独立重现器在修复前复现同一 panic，修复后两项通过。
Windows 完整库测试与最终下载双包页面验收仍是门禁。

保留 fix6 的双预算分页：以 25 轮为目标上限，普通页至多 64 MiB，并只在完整 JSONL
记录边界切页。持久索引 v4 保存连续边界；180.22 MiB 首屏、64.66 MiB 第 13 页以及
65 MiB 单记录结构均有回归。单记录巨型内容采用每次最多 32 KiB 的两遍流式 JSON/
UTF-8/哈希校验及有界预览，总 I/O 随记录长度增长；保留原 session/path/byte range/
SHA256，明确 previewOnly，不伪称目标已获得完整原文。原始历史文件不改写。
真实构建状态、页面预算、未提交记录、非法游标、源变化及解析错误分别显示；
前置失败不启用半份业务历史、不替换原 Agent/session，保留重试。

最终双包验收从实际 Tauri/Web 输入区切换及连续发送，独立检查目标请求实际获得的早期
要求、修改理由、失败尝试、安全边界与最新状态，原始 JSONL 哈希不变；每种结构两轮
消息各观察约十秒，末段消息、回复和耗时均须唯一，保留真实过渡采样，不只截第一帧。
