# Codeg v0.29.0-fix1

## Large long-running conversations open without scanning the whole rollout

- Makes every ordinary conversation open, switch, refresh and branch open use
  a bounded opaque-cursor page. Legacy index-window selectors can no longer
  turn an ordinary Codex open into a full JSONL parse.
- Adds a persistent, incremental byte-offset index for Codex user messages,
  turns, tool events and compaction boundaries. A missing index falls back to
  a tail scan capped at 16MB while resumable indexing continues in the
  background.
- Splits historical deliverables, source branches and branch-return records
  into independent lightweight pages. Large tool output, images, reasoning and
  return summaries load only after explicit expansion.
- Adds frontend and parser single-flight, request cancellation, generation
  guards and bounded LRU caches. A late response from an abandoned switch can
  no longer replace the active conversation.
- Makes deliverable and artifact events refresh only the visible turn's output
  associations instead of reloading transcript history.
- Keeps the virtualized message thread and scroll anchor stable while older
  pages prepend, and leaves the composer usable as soon as ACP is prompt-ready
  even if historical data is still loading.
- Adds privacy-safe performance logs for byte ranges, index/cache state, SQL,
  serialization, compression, transfer, JSON parsing and first interactive
  render.

No database migration is required. History indexes are rebuildable cache
sidecars under the Codeg user cache directory. Existing SQLite data and Codex
rollout JSONL files are neither rewritten nor truncated.

The Windows Setup and Windows Server Web packages include the same frontend;
the Server archive also contains the matching `codeg-mcp.exe` companion.

# Codeg v0.29.0-fix1 中文说明

## 大型长期会话无需扫描完整 rollout 即可打开

- 普通打开、切换、刷新和分支打开统一使用有界 opaque cursor 页面；旧的 index-window
  参数不再能让 Codex 普通打开退化为完整 JSONL 解析。
- 为 Codex 用户消息、turn、工具事件和 compaction boundary 增加持久化增量字节索引。
  索引缺失时先从文件尾部读取，硬上限 16MB，可恢复的后台索引同时继续建立。
- 历史产物、源分支和分支回归记录改为独立轻量分页；大型工具输出、图片、思考和回归
  正文只在用户明确展开后加载。
- 增加前端和 parser single-flight、请求取消、generation 防旧响应覆盖以及有上限的 LRU
  缓存。被放弃的旧切换请求不能再覆盖当前会话。
- 产物和文件事件只刷新当前可见 turn 的输出关联，不再重新加载消息历史。
- 向上分页时保持虚拟消息列表和滚动锚点稳定；ACP 到达 prompt-ready 后输入框即可使用，
  无需等待历史关联数据完成。
- 增加不含正文和凭据的结构化性能日志，覆盖字节范围、索引/缓存、SQL、序列化、压缩、
  传输、JSON 解析及首屏可交互耗时。

本版本不需要数据库迁移。历史索引是 Codeg 用户缓存目录下可重建的 sidecar；既有 SQLite
数据和 Codex rollout JSONL 不会被重写或裁剪。

Windows Setup 和 Windows Server Web 包含同一套前端；Server 压缩包同时包含匹配版本的
`codeg-mcp.exe` 伴生程序。
