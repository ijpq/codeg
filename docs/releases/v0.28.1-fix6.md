# Codeg v0.28.1-fix6

## Codex internet citations retain their real sources

- Preserves exact citation IDs, URLs, titles, domains, source kinds, call IDs,
  message IDs, offsets, and snippets across ACP tool updates instead of keeping
  only the private citation marker in assistant text.
- Bridges verified structured citation metadata from the bundled
  `codex-acp` 1.6.2 adapter and, when a provider reports `results: null` live,
  recovers only the current turn's exact `web_search_end` mappings from a
  bounded rollout tail before the terminal event is published.
- Keeps live WebSocket snapshots, refreshed conversation history, branches,
  copied text, and plain-text chat channels on the same citation model.
- Renders safe HTTP(S) sources as reusable clickable numbers with title/domain
  hover text. Unsafe schemes are rejected, and genuinely missing metadata is
  shown as a compact “source missing” state without inventing a URL.
- Adds privacy-safe diagnostics that identify the first missing stage and
  resolved/unresolved counts without logging prompts, credentials, or page
  content.

Existing rollouts are not rewritten. Historical conversations recover sources
when their rollout contains an exact citation-ID/URL mapping; ambiguous old
markers remain unlinked by design.

The Windows Setup and Server Web packages contain the same updated interface.

# Codeg v0.28.1-fix6 中文说明

## Codex 联网引用保留真实来源

- 在 ACP 工具增量中完整保留引用 ID、URL、标题、域名、来源类型、调用 ID、
  消息 ID、正文位置和摘要，不再只留下回答正文中的内部引用标记。
- 对打包的 `codex-acp` 1.6.2 派生适配器补齐结构化引用转发；如果上游实时
  事件返回 `results: null`，则在发布轮次终态前，仅从当前轮 rollout 的有界尾部
  恢复 `web_search_end` 中可核验的引用 ID 与 URL 映射。
- 实时 WebSocket、刷新后的历史会话、分支上下文、复制正文和微信等纯文本通道
  统一使用同一份引用模型。
- 安全的 HTTP(S) 来源显示为可复用编号，可点击并查看标题和域名；危险协议会被
  拒绝，真正缺少元数据时仅显示简洁的“来源缺失”，不会猜测或伪造网址。
- 新增脱敏诊断日志，记录元数据首次缺失阶段及已解析/未解析数量，不记录提示词、
  凭证或网页正文。

本版本不会改写原始 rollout。旧会话只在原记录中存在明确引用 ID/URL 映射时恢复
链接；无法确定来源的旧标记仍保持无链接降级显示。

Windows Setup 与 Server Web 使用同一套更新后的前端资源。
