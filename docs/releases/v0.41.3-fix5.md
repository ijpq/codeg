# CodeG 0.41.3-fix5

Windows Server 与 Setup 共用 Pi 上下文压缩和执行状态修复，并补齐恢复历史与实时回复
重叠时的压缩卡片收敛。fix4 的 Server 最终包门禁捕获了终态短暂残留运行卡片；旧版未正式发布。

此前去重仅处理独立卡片且保留首次记录，遗漏回复步骤中的同一压缩。现在按原生 eventId
与 ACP callId 的明确关联去重，优先真实完成/失败/取消，显式运行态仍优先于普通工具的
默认已完成状态；不猜测时间相近的事件，不丢弃正文，不合并不同压缩。新增回归修复前失败，
修复后通过；补实际渲染及三身份桥回归。最终页面验收保留原子 DOM 取样及过渡证据。

宿主另保留稳定 `lifecycleId`，原生完成历史同时保留原生 `eventId`；客户端漏收实时完成
事件后，仍能将旧开始记录与完成历史准确对齐。旧持久记录的别名从既有主键恢复，
不猜测时间、不改原生文件；新增漏事件回归修复前失败、修复后通过。

继续包含同一个 prompt 在原生压缩期间的可靠受理、有界健康查询、新旧 compaction 事件、
先确认原生 idle/所属进程树退出再结算取消或故障，以及按业务/session/连接持久化的压缩
生命周期和真实原因。显示真实阶段、已耗时及统一终态；不制造百分比、不重发 prompt，
不把后台仍在执行的任务提前标为失败。原生 JSONL 与用户业务历史不改写。

保留独立 Agent session、业务上下文增量、恢复队列、多 Provider、Fast 请求档位、外部投递、
整轮耗时、原生 Plan/Goal、产物和 Office 交付审阅、虚拟列表和正常追底。
本轮不迁移本机 Pi 基础设施、不新增基础配置同步层，不操作用户当前 Server/Setup。

运行组：Pi ACP `0.0.34-codeg.5` / `580f786dd9c5c18513971a419ad136330b493531`，
Pi `1.4.0`、Node `24.16.0`；Codex CLI `0.162.1-codeg.1` / ACP `2.2.2`；
codeg-mcp 与 CodeG 同版。upstream 基线 `v0.41.3` /
`ddd1f09fc5dd2f464e68bb4b5a2bbf51257ecfc5`。保留上游许可证、匹配资源、运行依赖及迁移。

Windows 双包须通过精确提交 CI、隔离新装/旧数据升级、最终随包运行时实际输入框发送、
长历史原生压缩超过 30 秒、回复一次及下一轮、切页/刷新/多端/重启、失败/取消/重试、
回滚和正式下载复验。全部成功后才可按真实路径、挂载、所有者、时间和进程占用审计并清理
本次可重建缓存；排除 Docker/容器、锁/socket、活动内容，保留源码、用户数据、包和最终日志。
