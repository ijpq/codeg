# 0.41.2-fix2 — business recovery and verified composer identity

Retains the complete unpublished recovery/context changes described in
[fix1](v0.41.2-fix1.md), including independent native Agent sessions, stable
business bindings, ordered readiness receipts, exact business-context coverage,
the full applicable-rule bridge and durable message queues. All prior Pi,
external delivery, service-tier, duration, artifact, Office, native Plan/Goal
and virtualized-scroll gates remain in scope.

A new regression reproduces a tab-persistence defect: a remote tab snapshot and
a later local selection can reach one React effect. The old one-shot skip
discarded the local save indefinitely. Saves now compare the actual baseline
payload, retaining remote echo suppression and the existing CAS/debounce.

Full draft acceptance also exposed an invalid test assumption: refreshing before
the 500ms focus save could restore its explicitly created detour conversation,
and an unscoped editor sent there while the test polled the original business.
The harness now verifies actual tab/panel/business/Agent identity before input
and waits for persisted focus before a reload. It never reselects the tab after
that reload, waits for native readiness or prewarms recovery. Native-request
counts, full replies, queue clearing and old-data upgrade assertions remain.

bundled native runtimes: fresh sessions, old fix6 data, input during a five-second
restore, consecutive rounds, in-place tab changes, reload, connection loss,
Codex/Pi handoff, retry and a real process restart. Setup installation,
in-place upgrade, offline rollback, Server upgrade, shared assets/migrations and
matching runtime hashes are independently checked. Fix1 publication was blocked;
its tag and failed diagnostics are preserved, and its version is not reused.
