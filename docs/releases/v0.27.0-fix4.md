# Codeg v0.27.0-fix4

## Reliable large Codex session restore

- Keeps one backend-owned restore flight alive for the complete Initialize,
  resume/load, selector, prompt-readiness, and binding lifecycle. Closing or
  refreshing a browser request no longer abandons a running Codex writer.
- Coalesces duplicate browser/provider restores and serializes different
  conversation rows that reference the same external session, preventing
  duplicate ACP processes and `active writer` races.
- Gives persisted restores a separate five-minute default timeout, configurable
  with `CODEG_ACP_RESTORE_TIMEOUT_SECS`, while keeping the browser request alive
  long enough to receive the server's bounded result.
- Keeps long `session/resume` operations out of idle cleanup, does not expose a
  historical connection as ready before its session is attached, and skips a
  redundant `session/load` when Codex reports an existing active writer.
- Reclaims only the failed connection's ACP/Codex/codeg-mcp process tree on
  disconnect, replacement, cancellation, or restore timeout; other sessions
  remain untouched.
- Starts Codex restore in parallel with paged transcript loading and limits the
  conversation detail's file-change runs to the visible history window instead
  of shipping the whole conversation ledger.
- Keeps the composer in a restoring state until the backend flight and attach
  replay complete. Stale requests cannot overwrite a newer generation, and an
  explicit retry starts one controlled restore rather than a timed client retry.

# Codeg v0.27.0-fix4 中文说明

## 大型 Codex 历史会话可靠恢复

- 将 Initialize、resume/load、选择器、prompt-ready 和会话绑定纳入同一个由后端持有的
  完整恢复任务；浏览器刷新、切换或请求中断不再遗留仍占用 writer 的 Codex 进程。
- 前端多个 Provider 的重复请求会合并，后端还会按 conversation 与 external session
  两层串行化，避免重复启动 ACP 进程和 `active writer` 冲突。
- 历史恢复使用独立的五分钟默认超时，可通过
  `CODEG_ACP_RESTORE_TIMEOUT_SECS` 调整；浏览器等待服务端给出有界的最终结果。
- 长时间 `session/resume` 持有明确恢复租约，不会被 idle sweep 清理；历史 session
  真正附加前不显示可用；Codex 已报告 active writer 时不再重复调用 `session/load`。
- 连接失败、替换、取消或恢复超时时，只回收该连接所属的 ACP/Codex/codeg-mcp
  进程树，不影响其他会话。
- Codex 恢复与分页历史加载并行；会话详情只返回当前可见历史窗口对应的文件变更轮次，
  不再附带整个长会话的文件变更台账。
- 前端在后端恢复和 attach replay 完成前保持“正在恢复”；旧请求不能覆盖新一代状态，
  明确重试也只会发起一次受控恢复。
