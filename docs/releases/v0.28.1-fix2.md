# Codeg v0.28.1-fix2

## Safe stale-run reconciliation

- Prevents a newly admitted or actively progressing Codex turn from being
  interrupted by the stale-run reconciler during prompt preparation.
- Associates live agent activity, artifact capture, and reconciliation with the
  exact durable turn run and connection generation instead of conversation-wide
  timestamps.
- Replaces the previous five-second single-sample decision with a configurable
  stale threshold (120 seconds by default) and a second unchanged observation
  after a confirmation window (15 seconds by default).
- Gives fresh agent activity, streaming output, active tools and restore work an
  explicit veto, while still repairing truly orphaned or silent zombie turns.
- Uses compare-and-set database updates and exact-run artifact settlement so an
  old reconciler cannot interrupt or demote a newer turn on the same conversation.
- Keeps a healthy ACP connection alive when only a stale durable row needs repair;
  process cleanup is reserved for a confirmed dead or terminal connection.

## Branch queue convergence

- Uses the current durable turn run—not stale browser `prompting` or
  `awaiting_persist` state—to decide whether Create Branch must wait. A
  `pending_review` conversation whose latest run is completed and settled is
  immediately eligible.
- Retries a genuinely busy source with one stable operation id and a
  low-frequency two-second lost-wakeup poll. The queue now distinguishes waiting for the
  source turn from actively creating the branch.
- Adds server-side operation-id uniqueness and validates the source conversation
  and fork point, so a reconnect with a different HTTP request id cannot create
  a second native or snapshot branch.
- Rejects missing persisted fork points instead of accepting a browser snapshot,
  and repairs legacy snapshot branches that claimed `prompt_ready` without a
  verified durable branch session.
- Preserves the stricter stale-run heartbeat/tool/connection checks for truly
  orphaned branch turns; this release does not infer that a database `running`
  row is dead without corroborating runtime evidence.

# Codeg v0.28.1-fix2 中文说明

## 安全的 stale run 对账

- 修复新任务刚进入或仍在正常运行时，被 stale-run 对账器在提示准备阶段错误中断的问题。
- 将智能体活动、产物捕获和对账精确绑定到当前 turn run 与连接代际，不再混用会话级旧时间戳。
- 将原先“5 秒后单次判定”改为可配置的 stale 阈值（默认 120 秒），并要求在确认窗口
  （默认 15 秒）后再次观察且状态完全未变化。
- 新鲜 ACP 活动、流式输出、正在执行的工具和恢复流程都会明确否决 stale；真正孤立或长期
  静默的僵尸任务仍会被清理。
- 数据库采用条件更新，产物 tracker 只允许精确 run 收口，旧对账任务不能中断或降级同一
  会话中后来启动的新任务。
- 仅修复陈旧数据库记录时保留健康 ACP 连接；只有确认连接或进程失效时才定点清理。

## 分支队列自动收敛

- “创建分支”是否等待改为读取后端当前有效 turn run，不再由浏览器残留的 `prompting` 或
  `awaiting_persist` 决定。会话即使仍是 `pending_review`，只要最新 run 已 completed/settled，
  就会立即开始创建。
- 源任务确实运行时，使用同一个 operation ID 每两秒做一次轻量复核，以补偿 WebSocket
  完成事件丢失；界面明确区分“等待源任务结束”和“正在创建分支”。
- 数据库新增 operation ID 唯一约束，并校验源会话与 fork point；即使重连后的 HTTP request
  ID 改变，也不会再生成第二个 native/snapshot 分支。
- 指定的 fork message 不存在时直接返回错误，不再用浏览器快照掩盖；旧的无
  `branch_session_id/session_verified_at` 却标为 `prompt_ready` 的快照分支会安全降级为
  provisional，保留原快照供重试。
- 对真正悬挂的分支 run 仍沿用本版严格的心跳、工具活动、连接与两阶段确认规则；不会仅凭
  数据库一条 `running` 记录就误杀任务。
