# CodeG v0.35.1-fix1

升级到 2026-10-11 发布的 upstream v0.35.1
（`e21eb6b38eea9405cdfa3b2d99df216d101d1344`），保留定制分支的有界近期历史、
跨客户端消息补偿、任务生命周期、非阻塞 AIR、native fork、MCP 和引用桥接修复。
本次重点解决超长 Codex 会话反复冷恢复及 CLI 同一次恢复中的重复完整读取。

## 修复

- 侧栏替换预览只释放前端 surface，保留就绪后端连接。继续使用服务端 single-flight、
  会话身份校验和既有 180 秒 idle GC；显式断开/取消/重配配置保持原语义。
- Windows Server ZIP 内置基于官方 Codex 0.162.1 的私有 `0.162.1-codeg.1`。
  为 ACP 的 excludeTurns 恢复读取经过校验的最新原生 compaction 和后续增量，上限
  64 MiB。保留原 session ID、原 rollout、完整历史及原生 writer 锁；不创建影子会话。
- 校验 replacement history、配置、runtime、轮次结束、world state、工具状态及文件
  identity/revision。不完整、损坏、回退、超大尾记录、追加、替换或标识不可用时，
  安全回退原生完整恢复。异步配置加载后重查元数据与配置，仅在同一 resume 请求且
  revision 未变时复用首次历史，避免配置阶段和 writer 阶段的重复完整读取。
- 包含匹配版本的 Server/MCP、Web 静态资源、计算机助手及完整私有 Codex Windows
  helper（含 sandbox service）/ripgrep 布局、内部校验和、源版本/补丁 pin 与许可证。
  code-mode host 使用上游源码 pin 的 Codex 自建 V8，保留 sandbox 特性及原依赖版本。
  数据库迁移编译进 Server，
  干净隔离数据目录的启动验证会实际执行迁移。

- 本地前端 9100 项、CodeG Rust 5108 项测试通过；CLI store 278 项、core 专项 2 项、
  原生 app-server thread_resume 集成 69 项通过。类型、lint、生产静态导出、cargo
  check 与 CodeG/变更 CLI 模块的严格 clippy 通过。保留既有 ignored 和失败诊断日志。
- 模型上下文对照在 JSON 编码前归一化隔离目录，修复 Windows 反斜杠转义引起的假差异；
  4 项专项测试通过，覆盖正斜杠技能路径，原有 6 份实际输入对照结果不变，未弱化上下文、工具或图片断言。
- 真实 ACP 2.1.1、2.2.2 与隔离 CodeG Server 验证冷/复用/并发打开、恢复后提问、
  原 session、工具配对及真实图片。冷/复用/并发打开只有一次 CLI resume；恢复阶段
  没有模型请求，提问只有一次模型请求并收到 end_turn。
- 4.44 GiB 合成样本、已建立元数据、新进程冷恢复：有效检查点 62.531 s→0.248 s，
  resume 实际读取 9,539,540,417→229,377 字节；重启 58.722 s→0.381 s。

  读取 9,539,540,091→4,769,909,310 字节；必要的一次完整恢复仍有成本。
- 校验原文件前缀、实际模型输入、坏尾、缺失/旧/无效检查点、缺少 runtime/settings、
  未结束轮次、超预算单条记录、追加与同名替换。文件完整保留，无 external_id 更换。
- 正式发布前要求精确 release SHA 的普通 CI 全部通过；Windows 构建和 Release
  校验会实际运行程序。发布后独立下载 Setup/Server 及 SHA256，检查版本、布局、
  checksum、解压、安装和隔离启动。

## 部署范围及已知限制

必须部署完整 Server ZIP，保留 `runtime/`；只有与编译 manifest 匹配时才自动选用。
`CODEX_PATH` 显式覆盖优先，`CODEG_USE_BUNDLED_CODEX=0` 禁用私有运行时选择，
`CODEG_LEGACY_CHECKPOINT_RESUME=0` 保留官方恢复路径。不会修改全局 CLI 或用户配置。
锁定适配器保持 2.1.1，最新 2.2.2 已作为兼容回归通过，不强行改变适配器版本组合。

Setup 使用现有上游 CLI 分发方式，不携带私有恢复 CLI；前端连接保留适用于两种模式。
本次性能优化面向 Server ZIP。仅有旧摘要的 session、首次元数据回填、失效检查点以及
超过 idle GC 的冷恢复仍可能慢；检查点恢复不会丢弃原历史或将前端分页冒充 Agent 恢复。

Linux 环境无法访问生产“2k自动化”原 rollout。以上性能是同一私有诊断二进制的
关闭/开启优化对照，CLI entrypoint opt-level=0、依赖 release；Windows 正式包使用
正常 release/thin LTO。合成文件使用密集可忽略 JSON 字段，元数据预先建立；
这些数字不等于生产 273 秒恢复的现场优化结果。未停止、替换或重启生产 CodeG。

完整责任边界、复现方法和测试条件见
[超长会话恢复诊断](../codex-long-session-resume.md)。

Windows 私有运行时的独立构建还保留官方 CRLF SQL 迁移字节，避免已有 SQLite 迁移
校验失败。内嵌权限模板等未修改资源使用 Git 官方 Windows checkout 字节格式，
私有补丁、二进制及强制 LF 资源保持原样。只处理独立编译源；数据库和校验记录
保持原样，迁移校验继续启用。新增八项跨平台构建回归，全部 67 条官方 Windows
合成数据库迁移记录逐一匹配。
