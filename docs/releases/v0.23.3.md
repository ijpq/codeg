# Codeg v0.23.3

## CI-verified upstream sync and upload quota correctness

Codeg v0.23.3 contains the complete v0.23.2 upstream sync and deliverable
accuracy work, plus the post-release CI correction on the exact commit shipped
by this release.

- Keeps `publish_deliverables` declarations and filesystem inference together:
  the conversation ledger remains inclusive, while reply-tail outputs require
  strict turn attribution.
- Keeps web attachment uploads unlimited by default, with an optional
  `CODEG_UPLOAD_MAX_ATTACHMENT_BYTES` operator cap.
- Reconciles `Content-Length`-based quota reservations with unlimited uploads,
  allowing small uploads under small server quotas without weakening the hard
  total-byte boundary for concurrent or chunked uploads.
- Removes the rebase-generated Rust warnings that caused the v0.23.2 main-branch
  Test workflow to fail under `clippy -D warnings`.

# Codeg v0.23.3 中文说明

## CI 验证的上游同步与上传配额修复

Codeg v0.23.3 包含 v0.23.2 的完整上游同步和成果物准确性改进，并把发版后修复的
CI 问题纳入本次实际发布的同一个提交。

- 保留 `publish_deliverables` 显式声明与文件系统推断：左侧对话成果物列表继续偏
  完整，对话回复尾端则只展示能严格归属到该轮的主要产物。
- Web 附件默认仍不限制单文件大小；运维可用
  `CODEG_UPLOAD_MAX_ATTACHMENT_BYTES` 显式设置上限。
- 将基于 `Content-Length` 的配额预留与不限大小上传正确合并：小文件可以进入较小
  的服务器总配额，同时并发上传和未知长度上传仍严格受总字节上限约束。
- 清理由 rebase 接缝产生的 Rust warning，修复 v0.23.2 主分支工作流在
  `clippy -D warnings` 下的失败。
