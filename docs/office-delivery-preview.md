# Office 交付审阅预览

自动预览现由当前业务对话的 `turn_run` 正常完成和产物结算驱动。
已删除 `changed_paths` → 扫描目录 → 自动打开 Office 标签的链路；创建、修改、删除、
其他对话在相同工作区的写入均不能直接触发自动预览。文件名和修改时间不用于判断终稿。

结算使用与产物卡片一致的本轮权威集合：显式声明成功、部分成功及有意空集合优先，
`replace`/`clear` 的最终结果生效；未声明时只使用已有规则认可且可靠关联的本轮推断产物。
先选有效可预览主产物，再按登记位置、路径和 ID 稳定排序选一个，不轮流弹出多个文件。
失败和取消不捕获审阅稿；原有效登记仍可通过产物卡片手动访问。

后台在结算放行下一任务前，为选中的 `.docx`、`.xlsx` 或 `.pptx` 复制真实字节，记录
run、产物 ID、文件名、SHA256 和完成时间。审阅副本位于数据库相邻的
`office-preview-cache`，属于需要保留的用户交付记录。原文件不移动、不改名、不重写。
复制限制 128 MiB、5 秒，拒绝复制期间发生变化的源文件；失败明确记录并继续结算任务。
转换在页面打开副本时进行，不参与任务状态，不会无限阻塞任务完成。

现有 OfficeCLI 渲染器读取稳定副本。手动打开 Office 文件也先取得只供该预览生命周期
使用的副本，防止下一轮制作过程刷新已打开的审阅内容。副本在相应 watch 进程结束后释放。
同路径再次交付使用新的内容副本并重建该预览；另存路径打开新标签，其他手动标签保留。
侧栏标明“本轮交付审阅”、文件名、完成时间和轮次短 ID；下载按钮读取相同副本。
手动查看未留存版本的旧记录明确标记“当前文件 · 打开时的稳定副本”，不能声称历史快照。

前端只监听当前活动业务的结算事件，不在刷新或进入对话时补弹历史。SQLite run 顺序、
每后端的已处理游标、并发读合并及选择代次，防止重复事件、旧响应、对话切换和用户关闭
后抢回焦点。非对话工作台页面和隐藏浏览器页面不自动打开。重新进入后从准确轮次的
产物卡片“在 CodeG 中查看”打开已留存审阅稿。
读取结果按持久轮次顺序处理；旧轮次重复事件不能使正在读取的新交付结果失效。

没有可预览交付时不弹空面板；复制或转换失败明确反馈，保留产物下载和手动查看入口。
OfficeCLI 是现有可选转换器；没有安装时显示已有安装提示，不假装已经成功预览。
远程桌面窗口仍明确提示使用服务器 Web 界面预览，不冒称支持原来未支持的 iframe 场景。
Agent 使用 OfficeCLI resident 时仍须 save/close，再登记交付；CodeG 只能冻结已写入磁盘
的交付字节。无法确定旧轮次版本、或已有后续工作开始时，不从当前覆盖文件补造历史副本。

回归包含权威集合替换/撤回、主文件稳定选择、无产物、失败/取消、有界失败、同路径和
新路径、历史防伪、重复事件、迟到读取和用户选择优先；双端验收使用真实 Pi/MCP、
OfficeCLI 1.0.158 与隔离模型端点，检查实际卡片、侧栏文本、SHA256、三种格式和刷新手动查看。

Windows Tauri 2.12.4 的 path 初始化脚本可能在嵌入 Office 页中缺少框架全局对象。
验收通过 CDP 核对准确脚本及子 frame 后单独保留这类框架异常，不把它当作文档转换成功
的证据；仍检查实际可见内容及下载字节。主页面、转换器和其他未知异常均阻止发布验收通过。
